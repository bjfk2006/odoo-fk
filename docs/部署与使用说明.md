# 易新建筑进销存系统 — 部署与使用说明

> 基于 Odoo 19 社区版 + 自研模块（采购在途跟踪 / 品牌界面 / 演示数据）。
> 本文档可在**任意一台新服务器**上从零部署，并说明日常使用与运维。

---

## 一、系统组成

| 模块 | 作用 | 是否默认安装 |
|---|---|---|
| Odoo 19 社区版 | 平台底座（产品/库存/采购/会计…） | ✅ 镜像自带 |
| `purchase_transit` | 采购**在途/船运跟踪**（中国→斐济，里程碑看板） | ✅ |
| `yixin_branding` | 品牌与界面定制（蓝色 logo、主题、菜单精简、设置开关等） | ✅ |
| `yixin_demo` | **演示数据**（钢材/ALC 等 18 种带图产品、库存、采购单、在途记录） | ⬜ 可选 |

四大功能：**①物资主数据 ②库存业务 ③单据与图片 ④采购在途/船运可视化**。

---

## 二、前置要求

- 一台 Linux 服务器（推荐 Ubuntu 22.04+），**2 核 4G 内存、20G+ 磁盘**起步。
- 已安装 **Docker 20+** 与 **Docker Compose v2**。
- 服务器可访问外网（拉镜像、`git clone`）。
- **放行入站端口 8069**（云服务器需在**安全组/防火墙**里开 8069，否则浏览器打不开）。

### 如未安装 Docker（Ubuntu 示例）
```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
docker version && docker compose version   # 验证
```

## 三、部署步骤（从零）

```bash
# 1) 拉取代码
git clone https://github.com/bjfk2006/odoo-fk.git
cd odoo-fk
git checkout feature/purchase-transit

# 2) 一键启动（自动拉取 postgres:16 + odoo:19 镜像，运行本仓库源码，
#    首次启动自动建库 odoo 并安装 purchase_transit + yixin_branding）
docker compose up -d

# 3) 跟踪初始化日志，等到出现 "HTTP service (werkzeug) running"
docker compose logs -f odoo
#    首次约需 1~3 分钟（要安装一批依赖模块），看到该行即就绪，Ctrl+C 退出日志
```

### （可选）灌入演示数据
> 想要一套现成的展示数据（带图钢材产品、库存结存、采购单、在途看板）就执行；
> 生产环境**不想要演示数据则跳过**。

```bash
docker compose run --rm odoo \
  -d odoo --db_host=db --db_port=5432 --db_user=odoo --db_password=odoo \
  --addons-path=/opt/odoo-src/addons --data-dir=/var/lib/odoo-data \
  -i yixin_demo --stop-after-init --no-http
docker compose restart odoo
```

## 五、日常运维命令（在 `odoo-fk` 目录内执行）

| 操作 | 命令 |
|---|---|
| 启动 | `docker compose up -d` |
| 停止（保留数据） | `docker compose down` |
| 重启服务 | `docker compose restart odoo` |
| 看日志 | `docker compose logs -f odoo` |
| 查看状态 | `docker compose ps` |
| **彻底删除（连数据卷一起）** | `docker compose down -v` |

### 改了模块代码后，让其生效
```bash
git pull                                   # 拉最新代码
docker compose run --rm odoo -d odoo --db_host=db --db_port=5432 \
  --db_user=odoo --db_password=odoo --addons-path=/opt/odoo-src/addons \
  --data-dir=/var/lib/odoo-data -u <模块名> --stop-after-init --no-http
docker compose restart odoo
```

### 数据库备份 / 恢复
```bash
# 备份（导出到当前目录）
docker compose exec -T db pg_dump -U odoo -Fc odoo > odoo_$(date +%F).dump
docker run --rm -v odoo-fk_odoo-web-data:/d -v $PWD:/b alpine \
  tar czf /b/filestore_$(date +%F).tgz -C /d .

# 恢复（到一个空库）
cat odoo_YYYY-MM-DD.dump | docker compose exec -T db pg_restore -U odoo -d odoo --clean --if-exists
```

## 六、使用说明

### 6.1 物资主数据（产品）
**库存 → 产品 → 产品**（或采购 → 产品）。
- 每个产品含：名称、内部参考号（编码）、类别（工程物资/备件/耗材/办公）、单位、销售价/成本、供应商、**图片**、最低库存等。
- 新建：点「新建」→ 填字段 → 点右上「**保存**」。

### 6.2 库存业务
**库存** 应用：
- **入库/出库**：收货单、发货单、内部调拨（采购确认后自动生成收货单）。
- **盘点**：库存 → 操作 → 实际数量调整。
- **库存预警**：库存 → 产品 → 补货规则（低于最低库存会提示补货）。
- **结存台账**：产品上的「在手数量」、库存报表。

### 6.3 采购与在途/船运跟踪（核心）
1. **采购 → 订单 → 新建** 采购订单 → 选供应商、加产品行 → **确认**。
2. 订单页点「**生成在途跟踪**」→ 每个订单行生成一条在途记录。
3. **采购 → 在途跟踪**：打开记录，填写船名/航次/柜号/提单号，以及各**里程碑日期**：
   工厂发货 → 集港装柜 → 开船(ETD/ATD) → 中转 → 到港(ETA/ATA) → 清关 → 签收。
4. **看板视图**：按里程碑分列（已开船/已到港/已清关/已签收），延误自动高亮。
5. **收货闭环**：在采购收货单上「验证」收货后，对应在途记录的「实际签收」**自动回填**、状态自动变「已签收」。

### 6.4 界面显示开关（设置）
**设置 → 通用设置 →「易新界面 / Yixin UI」**：
- ☐ 显示讨论应用　☐ 显示应用菜单　☐ 显示顶部通知
- 默认全部**隐藏**；勾选并保存后**刷新页面**即显示。

### 6.5 用户与权限
**设置 → 用户与公司 → 用户 → 新建**：
1. 填姓名、登录邮箱 → 点右上「**保存**」。
2. 在「访问权限」页：**角色**选「用户」（普通员工，别选管理员）；下面按应用配权限：
   - 采购：用户/经理　库存：用户/经理　**Transit Tracking：物流专员/物流经理**　会计：…
3. 设密码：保存后 → 操作（⚙）→「更改密码」（无需发邮件）。

> 权限三层：**用户组（角色）→ 访问权限(增删改查)→ 记录规则(行级过滤)**。多公司/数据隔离由记录规则自动处理。

## 七、常见问题

| 现象 | 处理 |
|---|---|
| 浏览器打不开 `:8069` | 云服务器**安全组**没放行 8069 入站；主机已监听（`docker compose ps` 正常） |
| 找不到「保存」按钮 | 已改为右上角蓝色**「保存」文字按钮**（仅在有未保存改动时出现），或按 **Alt+S** |
| 改了样式没生效 | 浏览器硬刷新 **Ctrl/Cmd + Shift + R**（清缓存） |
| 想装/卸某模块 | `-i`/`-u`（见 §五）；卸载在「应用」里（默认隐藏，可在设置里临时打开「显示应用菜单」） |
| 首次启动慢 | 正常，要安装依赖模块，等日志出现 "HTTP service running" |

## 八、卸载 / 重置

```bash
docker compose down -v        # 停止并删除容器 + 数据卷（数据全清）
# 如需彻底清理，再删代码目录与镜像：
cd .. && rm -rf odoo-fk
docker rmi odoo:19 postgres:16   # 可选：删镜像
```

重新部署回到「**三、部署步骤**」即可。界面定制与（可选）演示数据都会自动重建，
**仅手工建的账号/改的密码/手工录入的业务数据不会保留**（这些不在代码里）。
